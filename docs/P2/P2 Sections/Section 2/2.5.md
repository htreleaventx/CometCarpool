# 2.5 Assumptions and dependencies

| # | Assumption or dependency | What breaks if it does not hold |
| :--- | :--- | :--- |
| A1 | A sufficient number of students will be willing to offer and request rides with compatible routes and schedules | If student participation is too low, passengers may be unable to find suitable rides, significantly reducing the system's usefulness |
| A2 | University-issued email addresses will be sufficient to verify users' eligibility without requiring integration with university authentication systems | If email verification is insufficient, additional identity verification methods or university system integration may be required, increasing project complexity and development time |
| A3 | We assume that students will be able to coordinate carpools effectively using predefined pickup locations, destinations, and departure times without requiring real-time vehicle tracking or automatic route optimization | If students require real-time coordination or more flexible route planning, the proposed functionality may be insufficient, requiring additional features and increasing development complexity |

## Assumptions Review

The original assumptions from P1 were reviewed against the current P2 requirements, use-case analysis, and project scope.

| ID | Status | P2 Findings | Next Steps |
| :--- | :--- | :--- | :--- |
| A1 | Unresolved | The system supports ride offers, requests, and schedule matching, but sufficient student participation has not been validated. | Gather feedback from UTD students to evaluate interest and expected participation. |
| A2 | Unresolved | UTD email verification is planned, but its effectiveness in confirming user eligibility has not yet been tested. | Test the verification process and evaluate whether additional checks are necessary. |
| A3 | Unresolved | The use cases support ride coordination through manually entered locations, dates, and times. However, usability without real-time GPS has not been validated. | Test ride coordination scenarios and gather feedback on whether the available information is sufficient. |

## Review Summary

All three original assumptions remain applicable to the current project scope.

P2 analysis has not identified any evidence requiring changes to the assumptions. However, none have been fully validated, 
and further testing or user feedback is needed.

The original assumption IDs (A1-A3) have been preserved. No changes to the assumptions themselves are proposed.
