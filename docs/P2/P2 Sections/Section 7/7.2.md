# 7.2 Trade-Off Summary

## Overview

This section summarizes the architectural trade-offs identified in the Architecture Decision Records documented in Section 7.1.

Each trade-off describes the quality attribute favored by an architectural decision, the architectural approach selected, and the cost or disadvantage accepted.

The summary provides a consolidated view of the major design decisions influencing the Comet Carpool System.

## Architectural Trade-Offs

| Quality Favored | Architectural Move | Cost Accepted | Recorded In |
| :--- | :--- | :--- | :--- |
| Maintainability & Separation of Concerns | Adopt Layered (N-Tier) architecture with separate frontend, backend, domain and data layers | Additional communication between layers and coordination when changes effect multiple components | ADR-01 |
| Security and Access Control | Use Spring Security with JWT to enforce authentication and authrization in our banckend | Additional token management, security configs, and authentication testing | ADR-02 |
| Reliability and Data Consistency | Use PostgreSQL with Spring Data JPA/Hibernate for centralized persistence | Database dependency, ORM config and potential database performance bottlenecks | ADR-03 |
