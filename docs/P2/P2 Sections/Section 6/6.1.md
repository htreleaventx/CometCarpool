# 6.1 Architectural Drivers: Quality-Attribute Scenarios

## Overview

This section identifies the quality attributes that influence the architectural design of the Comet Carpool System.

Each quality-attribute scenario describes a condition the system must handle, the expected response, and a measurable criterion for determining whether the architecture satisfies the requirement.

At least three quality-attribute scenarios are required, derived from the quality requirements defined in Section 3.

## Quality-Attribute Scenarios

| QAS | Quality Attribute | Stimulus | Artifact | Response | Response Measure | From |
|:---|:---|:---|:---|:---|:---|:---|
| QAS-01 | Performance | User searches for available rides or ride requests while up to 50 users are accessing the system | Ride search functionality, SpringBoot  RestAPI, PostgreSQL database | System processes the search request and returns the matching results | At least 95% of our 100 search requests return within 2 seconds under the normal load (up to 50 concurrent users) | QR-01 |
| QAS-02 | Message Delivery Performance | User sends an in app message to another user while both have an active internet connection | In app messaging functionality, backend messaging API, database | System processes the message and delivers it to the respected recipient | At least 95% of 100 test messages are delivered within 3 seconds while both users have an active internet/data connection | QR-02 |
| QAS-03 | Reliability | User submits a valid ride posting, ride request, review, report, or recurring schedule update during normal operation | SpringBoot backend, Spring Data JPA/Hibernate, PostgreSQL database | System processes and stores the submitted data/information | At least 99% of 100 valid save operations are successfully stored during our normal operation | QR-03 |
| QAS-04 | Usability | First time user attempts to post a ride or ride request after logging in without outside help | React frontend, ride posting and ride request forms | System provides a user interface that allows the user to complete the process by themself | At least 5 first time users are observed with each users completion time and needed for assistance recorded against the 3 minute requirment | QR-04 |
| QAS-05 | Security | Unauthenticated user attempts to access private account information, messaging, reviews, reports, or recurring schedule information | Spring Security, JWT authentication, protected Rest API endpoints | System checks authentication and denies access to unauthenticated users | Access is denied in 100% of unauthorized access tests across protected features | QR-05 |
| QAS-06 | Responsive Design / Usability | User accesses a primary system page using a mobile device with a screen width of 375 pixels or bigger | React frontend, repsonsive page layouts | System adjusts its layout to display readable content without requiring horizontal scrolling | All primary pages display correctly without horizontal scrolling when tested at 375px, tablet width, and desktop width | QR-06 |

## Architectural Constraints

Identify the constraints from Section 3 that influence the architecture.

| Constraint ID | Constraint | Architectural Impact |
| :--- | :--- | :--- |
| CON-01 | System shall restrict account creation and system access to members (NOT ATTENDING) of the UTD community | Account registration and authentication must restrict access to authorized UTD users. UTD email verification must be included in the account registration process. |
| CON-02 | System shall not process, store, or transfer payments between riders and drivers | The architecture won't include payment processing services, gateways, or transaction pages. | 
| CON-03 | System shall not provide real time GPS tracking of riders or drivers | The architecture won't require continuous GPS tracking services or real time location monitoring components. | 
| CON-04 | System shall not automatically import a students official class schedule | The architecture won't require integration with UTDs official class scheduling system. Users will manually enter their recurring schedule. |
