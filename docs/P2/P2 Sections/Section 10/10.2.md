# 10.2 Plan to P3

## Overview

This section describes the planned development activities and milestones following the completion of P2.

The purpose is to establish a clear plan for transitioning from analysis and high-level design into the next stage of the Comet Carpool project.

## P3 Milestone Plan

The team will transition from analysis and high-level design to implementation, integration, testing, and the final presentation. Tasks will be assigned according to the roles established in the team's working agreement.

| Milestone / Task | Target Date | Owner (Role) | Done When |
| :--- | :--- | :--- | :--- |
| P3 Development Setup | Nov. 11, 2026 | Project Manager, Developer | Development branches, environments, and React/Spring Boot/PostgreSQL setup are working. |
| Review P2 Requirements and Architecture | Nov. 12, 2026 | Analyst, Reviewer | Requirements, use cases, and architectural decisions are reviewed for implementation readiness. |
| Frontend — Login and Registration | Nov. 15, 2026 | Developer | React/TypeScript login and registration pages communicate with the Spring Boot API. |
| Backend — Ride Management API | Nov. 17, 2026 | Developer | REST endpoints support creating, searching, updating, and cancelling ride offers. |
| Frontend — Ride Posting and Search | Nov. 19, 2026 | Developer, Designer | Students can post and search for rides through a mobile-responsive interface. |
| Backend — Ride Request Management | Nov. 21, 2026 | Developer | REST endpoints support submitting, accepting, rejecting, and cancelling ride requests. |
| Frontend — Ride Request Management | Nov. 23, 2026 | Developer, Designer | Riders can submit requests, and drivers can review and manage them. |
| Recurring Schedule Functionality | Nov. 25, 2026 | Developer | Students can create and manage recurring schedules and view matching ride opportunities. |
| In-App Messaging | Nov. 27, 2026 | Developer | Riders and drivers can send and retrieve messages within the application. |
| Reviews, Ratings, and Reporting | Nov. 28, 2026 | Developer | Students can submit reviews and ratings, and report inappropriate behavior. |
| Frontend and Backend Integration | Nov. 29, 2026 | Developer | Frontend features communicate with backend APIs, and information is stored and retrieved through PostgreSQL. |
| System Testing and Bug Fixes | Dec. 1, 2026 | Tester, Developer | Core user workflows are tested, major defects are corrected, and authentication restrictions are verified. |
| Code and Requirements Review | Dec. 2, 2026 | Reviewer, Analyst | Implemented features are reviewed against requirements and architectural decisions. |
| Final Presentation Slides | Dec. 3, 2026 | Designer, Project Manager | Slides document the project, architecture, implemented features, testing, and team contributions. |
| Final Demonstration and Rehearsal | Dec. 5, 2026 | Entire Team | The application demonstration works, presentation responsibilities are established, and the team completes a rehearsal. |
