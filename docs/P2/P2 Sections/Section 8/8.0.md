# 8 Prototype Evidence: Architecture Spike

## Overview

This section documents the architecture spike conducted to evaluate a technical risk or architectural decision associated with the Comet Carpool System.

The purpose of the spike is to test a specific architectural question using a small implementation and measurable results.

The spike is not intended to represent the completed application. Instead, it provides evidence supporting or challenging an architectural decision.

---

## S-01 — Architecture Spike

### Spike Information

| Field | Description |
| :--- | :--- |
| **Spike ID and Title** | S-01 — Backend Authentication and Authorization |
| **Risk or Decision It Addresses** | R4 / ADR-02 / QAS-05 |
| **Question (Answerable Yes or No)** | Can the Spring Boot backend authenticate users using JWT and prevent unauthorized access to protected API endpoints? |
| **Set-Up** | Java, Spring Boot, Spring Security, JWT, PostgreSQL, and Postman. Tested user registration, login, token generation, and access to protected API endpoints. Backend implementation is located in `src/backend/` |
| **How It Was Measured** | Sent authenticated and unauthenticated HTTP requests through Postman and checked the returned HTTP status codes to determine whether access was granted or denied | 
| **Result (Numbers)** | Previous manual tests returned HTTP 200 for successful authenticated requests and HTTP 403 for rejected requests. The total number of tests and percentage of unauthorized requests denied have not yet been documented |
| **What It Changed or Confirmed** | Confirmed that Spring Security with JWT can support backend authentication and protected API access, supporting ADR-02 and helping mitigate R4 (unauthorized access to personal information). Further testing is required to verify QAS-05 |
| **Where to See It** | `src/backend/` contains the authentication implementation. Postman test results, measurements, and a README still need to be committed under `spikes/S-01/` |
