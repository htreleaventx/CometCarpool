## Working Agreement

The team follows the original P1 working agreement, with GitHub collaboration procedures documented in the [Comet Carpool Git Workflow](https://github.com/htreleaventx/CometCarpool/blob/main/docs/Git_Workflow.md).

### Communication

The team uses Discord for communication, coordination, and project updates. 
Team members discuss questions, clarify requirements, and communicate progress or blockers.

GitHub Issues and pull requests are used for task-specific discussions, reviewing changes, and recording feedback.

### Task Management

GitHub Issues are used to organize and assign tasks. Each issue identifies the work to be completed, 
its assigned team member(s), and any applicable deadlines or dependencies.

The GitHub project board is used to track task progress and provide visibility into the team's work.

Team members are responsible for updating their assigned tasks and submitting completed changes through pull requests.

### GitHub Workflow

The team follows the established Git workflow:

1. Update the local main branch before starting a new task.
2. Create a separate branch for each feature, bug fix, or documentation task.
3. Make changes and create commits with descriptive messages.
4. Push the branch to GitHub and open a pull request targeting main.
5. The Project Manager reviews the changes and requests corrections if necessary.
6. Resolve review feedback before approval.
7. The Project Manager approves and merges the pull request using a merge commit.
8. Delete the completed branch after merging and update main before starting the next task.

Direct changes to main are not permitted. Team members should not merge their own pull requests.

Merge commits are preferred over squash merges to preserve individual commit histories and contributions.

### Deadlines and Accountability

Team members are responsible for completing their assigned tasks by the established deadlines and communicating their progress.

If a task is blocked or cannot be completed on time, the responsible member should inform the team or Project Manager so the issue can be addressed.

Each contributor is responsible for the quality and completeness of their work, including responding to pull request feedback.
