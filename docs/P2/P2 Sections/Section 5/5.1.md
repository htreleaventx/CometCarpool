# 5.1 Domain Model

## Overview

This section presents the conceptual domain model for the Comet Carpool System.

The domain model identifies the important classes, their attributes, and the relationships between them. It represents the information required to support the use cases analyzed in Section 4.

The model focuses on the problem domain rather than implementation details.

## Model Explanation

The domain model consists of nine conceptual classes representing students, ride offers, ride requests, recurring schedules, ride arrangements, messages, reviews, and reports.

### Class Relationships

A Student can create multiple ride offers, ride requests, and recurring schedules. Each recurring schedule contains one or more schedule slots. 
RideArrangement represents an agreement between a driver and a passenger based on a ride offer or ride request. 
Students can exchange messages, leave reviews, and submit reports. Each participant may leave one review per ride arrangement.
### Attributes

The attributes support the actor inputs defined in Section 4.2. RideOffer and RideRequest store pickup locations, destinations, dates, and times. 
RideOffer also includes available seats. RecurringSchedule and ScheduleSlot represent the selected days and times. Status attributes track ride offers, requests, and arrangements.
