#### Initial Use Case — UC-03

| Field | Content |
| --- | --- |
| Identifier and name | UC-03: Search and Manage Ride Requests |
| Primary actor | Student Rider |
| Supporting actors | Student Driver (who responds to a posted request) |
| Preconditions — what must be true before it starts | The student rider must have an active CometCarpool account and be logged into the system. |
| Trigger — what starts it | The Student Rider opens the ride search / ride request feature from the portal to find transportation. |
| Postconditions — what is true when it succeeds | The student rider's ride request is successfully saved in CometCarpool, becomes visible to eligible drivers, and the Student Rider receives confirmation that the request was posted. |
| Requirements realised | FR-04, FR-05, FR-06, FR-11 |

#### Initial Use Case — UC-04

| Field | Content |
| --- | --- |
| Identifier and name | UC-04: Manage Recurring Schedules and Find Matches |
| Primary actor | Student Rider |
| Supporting actors | Student Driver (provides recurring availability that could match the rider's transportation needs) |
| Preconditions — what must be true before it starts | The student rider must have an active CometCarpool account, be a verified member of the UTD community, and be logged into the system. Student Drivers must have entered their recurring availability for the system to identify potential matches. |
| Trigger — what starts it | The Student Rider opens the recurring schedule feature to enter their weekly transportation needs. The system then finds students with compatible schedules. |
| Postconditions — what is true when it succeeds | The student rider's recurring transportation schedule is successfully stored in CometCarpool. The system has identified and displayed any compatible driver schedules, giving the rider an opportunity to initiate further ride coordination. |
| Requirements realised | FR-07, FR-08, FR-09 |

The detailed main success scenarios, alternative flows, and actor-system interactions for UC-03 and UC-04 are documented in **P2 Section 4.2 — Expanded Use Cases**.
