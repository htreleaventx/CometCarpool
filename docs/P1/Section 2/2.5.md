# 2.5 Assumptions and dependencies

| Assumption/Dependency | What breaks if it does not hold |
| :-------------------- | :------------------------------ |
| **Assumption:** A sufficient number of students will be willing to offer and request rides with compatible routes and schedules | If student participation is too low, passengers may be unable to find suitable rides, significantly reducing the system's usefulness |
| **Assumption:** University-issued email addresses will be sufficient to verify users' eligibility without requiring integration with university authentication systems | If email verification is insufficient, additional identity verification methods or university system integration may be required, increasing project complexity and development time |
| **Assumption:** We assume that students will be able to coordinate carpools effectively using predefined pickup locations, destinations, and departure times without requiring real-time vehicle tracking or automatic route optimization | If students require real-time coordination or more flexible route planning, the proposed functionality may be insufficient, requiring additional features and increasing development complexity |
