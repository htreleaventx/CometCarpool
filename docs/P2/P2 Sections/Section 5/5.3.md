# 5.3 Consistency Cross-Check

## Overview

This section documents the consistency checks performed across the use-case analysis, domain model, object interaction models, and requirements.

The purpose is to identify and correct inconsistencies between independently developed artifacts before proceeding to high-level architecture design.

## Cross-Check Results

### K1 — Actor Inputs and Domain Attributes

Verify that all information referenced by actors in Section 4.2 is represented by attributes in Section 5.1.

### K2 — Sequence Diagram Objects

Verify that each object appearing in the analysis sequence diagrams is either a conceptual class from Section 5.1 or a declared interaction object.

### K3 — Scenario Table and Diagram Messages

Verify that each sequence diagram message corresponds to exactly one row in its scenario table, using the same numbering.

### K4 — Non-Trivial Step Coverage

Verify that every non-trivial step identified in Section 5.2(a) is represented by at least one row in the scenario table.

### K5 — Requirements Traceability

Verify that every analyzed use case is connected to at least one functional requirement.

### K6 — Postcondition Verification

Verify that the final messages in each analysis sequence diagram establish the postconditions defined in Section 4.2.
