## Traceability Explanation

### Functional Requirements

Explain how functional requirements are realized through use cases, analysis classes, and architectural components.

The functional requirements are realized through use cases that describe how drivers, riders, and the system interacts to accomplish intended tasks. These use cases are further represented by analysis classes which define each part of the system's responsibilities. Architectural components implement these responsibilities to make the app fully function.

### Quality Requirements

Explain how quality requirements influence the architectural components and quality-attribute scenarios.

The quality requirements influence the design of the CometCarpool app. It establishes expectations for performance, reliability,  usability, and security. 

### Constraints

Describe how system constraints affect architectural decisions and component responsibilities.
only 
Constraints establish limitations that cannot be adjusted or negotiated. For example, restricting access to CometCarpool to only UTD community members requires the app to require a valid UTD email to successfully create an account. Excluding payment processing means the app will not be legally held liable for any potential financial problems. These constraints ensure that the architecture remains within the project's intended scope.
