## Expanded Use Case 1: UC-3 - Search and Manage Ride Requests 
Identifier and name: 
UC-03: Search and Manage Ride Requests

Primary Actor: 
Student Rider

Supporting Actors: 
Student Driver ( whe responding to a posted request)

Preconditions: 
The student rider must have an active CometCarpool account and be logged into that system.

Trigger: 
The Student Rider opes ride search / ride request feature from the portal to find the transportation feature. 

Main Success Scenario: 
1. The Student Rider opens the ride search feature in the CometCarpool.
2. Then, the system displays the ride search feature interface. 
3. The Student Rider enters their desired pickup location, destination, time, etc. 
4. The system searches for available rides matching the entered criteria. 
5. The system displays the available rides to the student rider. 
6. The student rider reviews the avaiable ride options and decides to create their own ride request. 
7. the student rider enters the required pickup location, destination, date, time and submits the ride request 
8. the system saves the request and make it available to eligible drivers
9. the system confirms the ride request was posted  

Alt & exc flows: 
A1- No matching rides: 
at step5, if no rides match the criteria, the system informs the rider that no matching rides were found. The rider may continue by creating a ride request. 
A2- Request cancellation: 
after posting a request, the rider may cancel it. the system updates the request status and removes it from the available requests. 

Postconditions: 
the student riders ride request is successfully saved in CometCarpool, becomes visible to eligible drivers, and the Student Rider receives confrimation that the request was posted. 

Requirements realised:
FR-04, FR-05, FR-06, FR-11

Use Case #2

Identifier and name: 
UC-04: Manage Recurring Schedules and Find Matches

Primary Actor: 
Student Rider

Supporting actors: 
Student Driver (provides recurring availibility that could match the rider's transportation needs at that time)

Preconditions: 
The student rider must have an active CometCarpool account, be a verified member of the UTD community, and be logged into the system. Student Drivers must have entered their recurring availibility for the system to ID potential matches. 

Trigger: 
THe student rider opens the recurring schedule feature to enter their weekly transportation needs. The ssytem then finds students with compatible schedules. 

Main Success Scenario: 
1. The student rider opens the recurring schedule in CometCarpool
2. the system displays the recurring schedule interface
3. the student rider selects the days of the week and the times they would regularly need a ride
4. the student rider saves their schedule
5. the system stores the schedule and cofnirms it was saved
6. the student rider selects the option to find compatible schedules
7. the system compares the riders needs agains the aavailibility entered by the drivers
8. the system displays potential matches with compatible days and times
9. the student rider reviews the potential matches and selects a driver theyd like to coordinate a ride with. 

Alt/ exc flows: 
A1- No comaptible schedules: 
at step 8, if no compatible driver schedules are found for a rider, the system will inform them and they may modify their schedule to search again 
A2- Missing schedule info: 
at step 4, if the rider has not selected the required days or times, the system identifies the missing info and requests some corrections before saving. 
A3- Driver saves availibility: 
A student driver opens the recurring schedule feature, selects the days and times they can provide transportation, and saves their availibility. The system stores the driver's schedule for future matching. 

postconditions: 
the student rider's recurring transportation schedule is successfully stored in CometCarpool. the system has ID'd and displayed any compatible driver schedules, giving the rider an opportunity to initiate further ride coordination. 

requirements realized: 
FR-07, FR-08, FR-09
