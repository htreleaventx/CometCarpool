## Quality Requirements Review

QR-01 through QR-06 were reviewed for testability and compared with the quality-attribute scenarios in Section 6.1. The requirement text above is unchanged, and the original requirement IDs are preserved.

Every quality requirement has a measurable threshold, a stated condition, and a verification method, and each is covered by exactly one scenario in Section 6.1.

### Testability Observations

These do not change any threshold. They are clarifications the team could approve so the tests are repeatable.

1. **QR-01 wording and test data.** The text says "concurring users", and Section 4.2 says "concurrent users". "Concurrent" is the intended word. The requirement also does not say how much data the search runs against, so the test should state the number of rides and ride requests stored.
2. **QR-02 and the messaging design (Q17).** QR-02 requires delivery to the recipient within 3 seconds. If messages are fetched by refreshing or polling, the polling interval must be short enough to meet the 3 second limit, or the delivery measure should be defined as "available to the recipient when their screen next refreshes". The team should confirm which one the messaging answer in Q17 means.
3. **QR-03 test sample.** "100 valid save operations across the features" does not say how the 100 are split among ride postings, ride requests, reviews, reports, and schedule updates. A fixed split would make the test repeatable.
4. **QR-04 test users.** The requirement says "first time test users". It should state that they have not seen the system before and are UTD students, to match the intended users.
5. **QR-06 screen sizes.** Only 375 px is given as a number. "Tablet width" and "desktop width" should be given numbers, for example 768 px and 1280 px, so the test is repeatable.
6. **QR-05 and the current backend.** The backend in `src/backend` currently allows unauthenticated access to the user list and does not check tokens on requests. QR-05 would fail if tested today. This is an implementation gap, not a problem with the requirement.
